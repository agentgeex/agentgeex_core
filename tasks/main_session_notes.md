# 主会话做笔记 - Main Session Notes

> **本文件不注册为 `agx_task_base` 行，因此不出现在 `agx_struct.json` 里 —— 这是设计，不是遗漏。**
> 它只作 `agx_note_main_session` 与 `agx_daily_log` step1 的 instruction 文本源
> （代码用 `_load_task_desc("main_session_notes")` 按名字读它），
> 实际派发时复用的是目标 Agent 自己的 `general` 任务。
> `scripts/verify_tasks.py` 认 `task_base: none` 这个标记，据此区分「故意不注册」与「孤儿文件」。

## 概述
**为 Agent 自己的主会话（main session）做"快照式"笔记的任务。**

主会话是 Agent 与人类伙伴的对话通道，承载了大量关键决策与讨论现场。
但它天然没有 execution 边界——内容是一段连续对话流，无法进入
「execution.summary → 日志汇总」的聚合管道。

本任务用一次 execution 把「做笔记」这件事结构化：执行者把**此刻**主会话中
正在发生/刚刚发生的事情，记录到本次执行的 `summary` 中，从而让主会话现场
拥有与其他工作现场一致的素材载体。

## 核心理念：快照，而非补记
- **什么时候执行，就记录那个时候的主会话内容**——不需要回溯更早的历史
- 执行得勤 → 细粒度快照；执行得疏 → 粗粒度快照
- 当天结算时，由日志汇总任务把所有快照统一整理成文
- 本任务**不追求完备性，只追求及时性**：漏掉的内容由后续快照自然承接

## 执行规范

### 1. 记录范围
只记录**事实与结论**，具体包括：
- 讨论了什么（议题、分歧、背景）
- 定了什么（决策、方案、结论）
- 留下了什么待办（下一步动作、待确认事项、遗留问题）

**不要记录**：寒暄、过程废话、与本时刻无关的历史内容。

### 2. 记录载体
- 记录写入 `agx_finish_task` 的 `summary` 字段（这是本任务的唯一产出）
- `summary` 应自足可读：即使脱离对话上下文，也能明白当时发生了什么
- 不要写入 `result`（本任务无结构化数据产出）

### 3. 结束流程
- 记录完成后，调用 `agx_finish_task(task_run_uuid, status="succeeded", summary=<笔记内容>)`
- 若本时刻主会话确实无内容可记，可如实记录（如"本时段无实质讨论"）并正常结案

## 输入规范
本任务不使用 task 模板中的 `x_desc` 作为执行指令来源（避免污染主会话上下文）。
调用方通过 `exec_instruction` 传入本次记录的补充说明（如"重点记录刚才定的方案"），
无补充说明时按默认快照语义执行。

## 输出规范
- `status`: succeeded（正常记录）/ failed（无法执行）
- `summary`: 本时刻主会话的快照记录（人类可读）
- `result`: 留空

## 适用场景
- Agent 主会话中发生了重要讨论或决策，需要沉淀
- 需要定期为主会话留痕，供当天日志汇总使用
- 由 `agx_note_main_session` 工具触发（未来亦可由看门狗定时触发）
