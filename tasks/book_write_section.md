# 任务：小节写作 (book_write_section)

## 概述
写作师接收策划编辑（book_planner）生成的标准化创作报文，创作或改写书稿小节。报文已内嵌本书介绍、相邻章节目录、当前文件内容、创作要求——写作师无需自行查找上下文。

## 输入
`instruction` 直接包含完整创作报文，格式如下：

```
《书名》

本书介绍：
{book_intro}

前一章目录：
{前一章 TOC.txt 内容，或"（无，此为第1章）"}

本章目录：
{当前章 TOC.txt，当前任务行带 ← 📝 当前任务}

下一章目录：
{下一章 TOC.txt，或"（无，此为末章）"}

当前任务：撰写 {文件名}

类型：{H2 导语 / H3 小节 / 独立 H2}

当前内容：
{文件在 split/ 中的当前内容，或"（新建文件，开篇创作）"}

---

创作要求：
1. ...
2. ...
3. 体现本书定位：务实、拒绝概念炒作、面向工程落地
```

**关键字段解析：**

| 字段 | 用途 |
|------|------|
| 书名 + 介绍 | 每次创作重新建立全局认知 |
| 三层目录 | 知道来处（前一章）→ 位置（本章）→ 去处（下一章），确保承上启下 |
| `← 📝 当前任务` | 一眼定位自己在目录树哪片叶子 |
| 类型 | 决定写作策略：导语概括铺垫 / 小节深入展开 |
| 当前内容 | 空 = 新创；有内容 = 改写/润色 |
| 创作要求 | book_planner 根据节类型和位置定制 |

## 写作流程

### Step 0: 获取书稿根目录

调用 `agx_get_project_config` 读取项目 `x_desc`，从 `## 书稿信息` 中提取 **书稿根目录** 的绝对路径。
本文中所有 `workspace/` 路径都相对于书稿根目录，不可使用 Agent 自身的工作目录。

### Step 1: 解析报文
1. 提取书名、本书介绍 — 锚定全局定位
2. 读三层目录 — 理解自己在全章/全书的位置
3. 确认类型 + 当前内容状态 — 决定是新创还是改写
4. 理解创作要求 — 每条都要逐一回应

### Step 2: 写作执行

#### H2 导语（`_00_` 文件）
- **定位**：承上启下，概括本节要点，为子节做铺垫
- **不要**：展开细节、举完整示例（留给子节）
- **长度**：精炼，通常 200-500 字
- **结构**：接住读者 → 点出本节要讨论的核心问题 → 自然引出第一个子节

#### H3 小节
- **定位**：围绕一个 H3 标题深入展开
- **不要**：重复导语内容、跳到其他节的话题
- **长度**：2000-4000 字
- **结构**：
  - 开头（~200 字）：接住读者——"你知道了 X，但 Y 呢？"
  - 核心（主体）：概念解释 → 案例/代码 → 分析解读。每个技术判断附证据
  - 结尾（~100 字）：总结要点，为下一小节留钩子

#### 独立 H2（无子节）
- **定位**：自身即为完整创作单元
- **结构**：同 H3 小节，但可以更完整

### Step 3: 输出文件

写入 `workspace/drafts/{chXX}/{文件名}`：
```markdown
{创作内容}
```

**文件名规则：**
- 新创：`{原文件名去掉 .md}_v1.md`（如 `01_01_00_理解大模型_v1.md`）
- 修改已有 `_vN`：递增版本号 → `_vN+1.md`

### Step 4: 自审
- [ ] 是否回应的所有创作要求？
- [ ] 内容是否与其他节连贯（不重复、不断档）？
- [ ] 术语是否一致（参照 `standards/glossary.md`，如有）？
- [ ] 技术判断是否有证据支撑？
- [ ] 语气是否符合本书定位（务实、拒绝概念炒作）？
- [ ] 字数是否在类型要求的范围内？

### Step 5: 结案
```
agx_finish_task(
  task_run_uuid={当前 run_uuid},
  status="succeeded",
  result={输出文件路径},
  summary="{文件名}：{改动说明，如'新创 H3 小节，2500 字'}"
)
```

## 异常处理

| 场景 | 处理 |
|------|------|
| 报文不完整或格式异常 | 不强行猜测，`agx_finish_task(status="failed")`，summary 写清缺少什么字段 |
| 当前内容为空但类型是改写 | 如创作要求说"改写"但内容为空 → 按新创处理，summary 中注明 |
| 引用了其他节的术语/概念 | 使用标准术语（glossary），避免本节未定义的专有名词 |
| 不确定某个技术细节 | 标注 `[待核实]`，不编造 |

## 执行约束
- 本节创作**不需要**读取其他节的 draft，报文已包含足够的上下文
- 只需读 `standards/` 下的 `glossary.md`（如存在），其他标准已在创作要求中
- 文件名版本号严格递增，不跳号
