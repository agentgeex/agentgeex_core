# 任务：书稿审校 (book_review_content)

## 概述
审校官对写作师产出的书稿小节进行多维质量检查。审校结果驱动修改循环——"不通过"会触发 writer 修改，改后再次审校，直到通过或人工裁决。

## 输入
`instruction` 包含审校报文：

```
审校任务：{文件名}

类型：{H2 导语 / H3 小节 / 独立 H2}

审校内容：
{drafts/ 中 _vN.md 的完整内容}

原稿参照：
{split/ 中对应 .md 的完整内容，或"（新创文件，无原稿）"}

可用的写作标准：
- standards/glossary.md — 术语统一表
- standards/writing_standard.md — 写作标准（如有）

---

本书介绍：
{book_intro}（帮助理解全书定位）
```

## 审校流程


### Step 0: 获取书稿根目录

调用 `agx_get_project_config` 读取项目 `x_desc`，从 `## 书稿信息` 中提取 **书稿根目录** 的绝对路径。
本文中所有 `workspace/` 路径都相对于书稿根目录，不可使用 Agent 自身的工作目录。
### Step 1: 建立比对基准
1. 读「原稿参照」— 如果是改写模式，原稿是评判"改得好不好"的参照物
2. 读「审校内容」— 这是 writer 的产出，逐字审
3. 如有 glossary/writing_standard，读之；没有也继续审（不阻塞）

### Step 2: 五维审校

| 维度 | 检查项 | 权重 |
|------|--------|:--:|
| **术语一致性** | 专有名词是否统一？前后用词是否一致？ | 🔴 |
| **内容准确性** | 技术描述无误？代码可运行？关键信息无遗漏？抽象不失实？ | 🔴 |
| **风格统一** | 语气符合作品定位？小节结构完整？字数在范围？ | 🟡 |
| **衔接连贯** | 与前后节不重复、不断档？内部逻辑流畅？ | 🟡 |
| **读者体验** | 开头接住读者？技术判断有证据？无跳跃困惑？ | 🟢 |

**导语（`_00`）附加检查：**
- 是否概括了本节（H2）的核心问题？
- 是否为子节做了有效铺垫（读者读完导语后应该想知道子节的内容）？
- 是否控制了长度（导语不宜长，200-500字）？

### Step 3: 输出审校报告

写入 `workspace/drafts/{chXX}/{原文件名_vN}_review.md`：

```markdown
# 审校报告 — {文件名}

**审校内容**: {draft 文件名，如 01_01_00_理解大模型_v1.md}
**类型**: {H2 导语 / H3 小节 / 独立 H2}
**总评**: {通过 / 有条件通过 / 不通过}

---

## 术语一致性
- ✅ 术语使用符合 glossary
- ❌ L42 "transformer" → 应统一为 "Transformer"（首字母大写）

## 内容准确性
- ✅ 概念解释清晰正确
- ❌ L78 代码示例缺少 import 语句，不可直接运行

## 证据链审查 (yes-md)

| 铁律 | 状态 | 问题 |
|------|:--:|------|
| 证据优于直觉 | ❌ | "研究表明"无引用；"相关资料"不具名 |
| 先调查再查问 | ❌ | 代码缺 `target_modules` 参数，copy 过去报错 |
| 修改必验证 | ✅ | （首版审校，下轮修后验证） |

## 风格统一
- ✅ 语气平实专业，无卖弄
- ❌ 开头 350 字，超导语推荐范围（200-500字），建议压缩

## AI 味检测 (humanize-chinese)

| 标记 | 行号 | 原文 | 建议 |
|------|------|------|------|
| 机械连接词 | L1 | "值得注意的是" | 删除，直接开篇 |
| 机械连接词 | L3 | "综上所述" | 段首用"综上所述"逻辑错误，删除 |
| 空洞措辞 | L12 | "具有重要意义" | 具体化：对什么有意义？ |

AI 味密度：3 处 / 300 字 = 中

## 衔接连贯
- ✅ 与导语自然衔接，未重复导语内容
- ❌ 结尾缺少对下一节（01_01_02）的钩子，建议加过渡句

## 读者体验
- 💡 第 3 段"token 和 embedding 的区别"对初学者可能跳跃较大，建议加一句类比

---

## 修改优先级
1. 🔴 L78 代码缺 import（必须改）
2. 🔴 L42 术语不规范（必须改）
3. 🔴 证据链：无引用来源、代码不可运行
4. 🟡 开头太长（建议改）
5. 🟡 结尾缺钩子（建议改）
6. 🟡 AI 味 3 处标记（建议去模板化）
7. 🟢 L3 embedding 解释可加类比（锦上添花）
```

### Step 4: 判定总评

| 总评 | 条件 | book_planner 后续动作 |
|------|------|---------------------|
| **通过** | 无 🔴 项，🟡 ≤ 0 | 标记该节为 "reviewed"，可进入 beta_read 或定稿 |
| **有条件通过** | 无 🔴 项，🟡 ≤ 3 | writer 修改建议项后直接定稿，无需重审 |
| **不通过** | 有 🔴 项，或 🟡 > 3 | writer 修改后重新审校，版本号 +1 |

### Step 5: 结案
```
agx_finish_task(
  task_run_uuid={当前 run_uuid},
  status="succeeded",
  result={审校报告文件路径},
  summary="{文件名}：{总评}，🔴{N}项，🟡{M}项，🟢{K}项"
)
```

## 修订循环协议


```
修订任务：{文件名}

审校报告：
{_review.md 中 🔴 和 🟡 项}

当前版本：
{_vN.md 内容}

修订要求：
1. 逐一处理审校报告中的 🔴 和 🟡 项
2. 输出 _v{N+1}.md
3. 如对某个审校建议有异议，在文件末尾注明 `[审校异议] {原因}`
```

## 异常处理

| 场景 | 处理 |
|------|------|
| 无 glossary 可参照 | 术语检查基于常识和一致性，不阻塞 |
| 原稿参照不存在（新创） | 不比对原稿，侧重内容质量和独立性 |
| 审校内容为空 | 直接标记不通过，summary 写"文件为空" |
| 不确定某技术点 | 标注 `[待核实]`，不强行判断 |

### Step 2.5: 技能辅助检查（强制）

>  以下两项是审校流程的强制检查点，不是可选的"参考"。

#### A. `yes-md` — 证据链审查

用 yes-md 三条铁律逐行审查，具体提问：

| 铁律 | 审校检查项 | 触发标记 |
|------|-----------|---------|
| **证据优于直觉** | 技术判断有引用来源？论文/文档/实验？ | 禁止词："大概""应该""可能""据说""研究表明""相关资料" |
| **先调查再查问** | 代码示例 copy 过去能运行？import 完整？参数合法？ | 缺 import、缺必传参数、未定义的变量 |
| **修改必验证** | 修订后审校时：writer 的修改是否真的修了问题？ | 跑了代码？读了日志？确认了输出？ |

审校报告中新增（放在 Step 3 报告模板的「内容准确性」之后）：
```markdown
## 证据链审查 (yes-md)

| 铁律 | 状态 | 问题 |
|------|:--:|------|
| 证据优于直觉 | ✅/❌ | {技术声明有无引用？有无无据措辞？} |
| 先调查再查问 | ✅/❌ | {代码可运行？缺什么？} |
| 修改必验证 | ✅/❌ | {如为修订审校：上轮问题修了？验证方式？} |
```

#### B. `humanize-chinese` — AI 味检测

逐段扫描 AI 写作标记，逐行标注：

**检测清单（每条逐行扫）：**

| 标记类型 | 示例 | 审校动作 |
|---------|------|---------|
| 机械连接词 | "值得注意的是""综上所述""由此可见""总的来说" | 标出行号，建议删除或替换 |
| 空洞措辞 | "具有重要意义""提供了高效且实用的解决方案" | 标出，要求具体化（有意义→具体是什么意义？） |
| 句式均匀 | 每句 25-35 字，无短句无长句 | 标记节奏问题，建议打破 |
| 模板化结构 | "首先…其次…最后…" 三连 | 标记，改自然过渡 |
| 完美结论 | 过于完整、确定、无风险的收束句 | 标记，改为自然收束或留下开放式钩子 |

审校报告中新增（放在「风格统一」之后）：
```markdown
## AI 味检测 (humanize-chinese)

| 标记 | 行号 | 原文 | 建议 |
|------|------|------|------|
| {机械连接词/空洞措辞/句式均匀/模板结构/完美结论} | L{N} | {引用原文} | {替换建议} |

AI 味密度：{标记数} 处 / {总字数} 字 = {高/中/低}
```

**注意**：AI 味检测不改技术内容、不换术语、不动代码。只改措辞和节奏。如果标记密度过高（>1 处/100 字），总评中说明，但不在 🔴🟡 里另外扣分——AI 味本身不是质量问题，是风格问题。
